k4 pre-registration (written before window open, 2026-11-02)
Change under test: gr.om CE kernel 21 (grce) runs one warp per row instead of one thread per row.
Lane l holds columns l + 32u and reads 8 coalesced 128-byte lines per step of 256 columns (k3 read
8 consecutive words per thread, 32 rows apart per warp). Pass 1: lane max, then 5-step SHFL.BFLY warp
max. Pass 2: per-lane Kahan sum of e = ex2(l log2e - m log2e) with no store (k3 stored e), lane total
s - c, then 5-step warp sum. Pass 3 recomputes e with the same FFMA and MUFU.EX2 as pass 2, scales by
sc/sum and stores. So one full-row write pass is gone: traffic is 3 reads + 1 write of R x V f32 (k3: 3
reads + 2 writes). The lane owning column y (y & 31) subtracts sc from L[y] and writes stats; the
other lanes exit first. The sum order changed (per lane, then tree), so results are NOT
bit-identical to k3. gg.om launches R*32 threads (arg 0 = R*32). grall refuses V not a multiple of 256.
New build-time mutant x (gr.om OMUTX 0): the CE warp sum skips the lane-1 butterfly step.
Mutant k (OMUTK 0) now removes Kahan from each lane's 128-term sum. It is run as an observation
only. It is NOT a control any more: [INFERENCE] its bias should be far below the 10 µnat gate.
