Change under test: causal chunk skipping in the softmax row kernels gr.om grsoftf (id 15) and
grsoftb (id 16). The k5 profile (evidence/OMEGALLM/gpu-k5/prof-K5.txt) has 8 launches per step of
each, grid 128x512x1, at about 224 and 228 GB/s each (WolframLanguageEvaluator b=512*256*256*4;
{2b/(9568788/8), 3b/(14096979/8)} -> {224.43, 228.50}): bandwidth-bound, so only traffic can drop.
 Loads: row t (R21) loads 32-column chunk u only if t >= 32u. Predicates P0..P6 = (t >= 32u) for
   u = 1..7 are set by ISETP before the loads (an ISETP between the loads would wait on their
   scoreboard); chunk 0 and chunks from u = 8 on stay PT (loaded, then masked). New encoders
   gk.om gkldgp/gkstgp put the guard in word 0 bits 12-15; gkldg/gkstg are now gkldgp/gkstgp with
   PT (p 7), so their words are unchanged.
 Stores: chunk u is stored only if t >= 64 floor(u/2) (P1, P3, P5 for chunk pairs 2-3, 4-5, 6-7,
   recomputed before the stores because the mask loop reuses P1). The causal GEMMs read a P or DS
   row only up to the end of its diagonal tile (S/DP id 35 GEMM64; P U, DS K, P^T DO, DS^T Q
   GEMM32 at E = 32, tile <= 64), so the chunks not stored are never read.
 grsoftb now also FSELs p to RZ for columns > t (unloaded p registers hold stale values); in K5 p
   there was exactly +0 from softf, so the value is the same.
Fixed latent encoder bug: gk.om gkisge put the destination predicate at word 0 bit 16; ISETP's is word
2 bit 17 (as in gkisetp). The first max-shape dump showed all seven ISETPs writing P0. Every
existing caller passes p 0, so their words do not change (static check below).
Exactness argument [INFERENCE until the run]: every value a consumer reads is computed from the same
inputs by the same instruction sequence as K5. Unloaded chunks lie wholly above the diagonal and are
replaced by FSEL (-inf in softf, +0 in softb) before any arithmetic, exactly as K5's loaded values
were. So K6 is predicted BIT-IDENTICAL to K5 on every output.
New build-time mutant w (gr.om OMUTW 0): load predicates t >= 32u + 32, so from chunk 1 on the
diagonal chunk of each row is not loaded and its stale register enters the softmax.
